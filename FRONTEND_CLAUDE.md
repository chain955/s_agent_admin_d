# FRONTEND_CLAUDE.md — Sport Agent Frontend

This file is the architectural anchor for the Sport Agent frontend project (`sport_agent_admin`). It is loaded into context at the start of every Claude Code session in this repo. It fixes decisions that the spec leaves open and that must stay consistent across all frontend stages.

The functional spec for the whole product lives in the **backend repo** at `docs/health_assistant_spec.md`. Sections relevant to this frontend:
- §1.1, §14, §15 — admin API surface and the admin UI requirements,
- §16 — testchat UI requirements,
- §4.5 — SSE event format (locked),
- §17 (and `docs/locked_decisions.md`) — locked backend decisions the frontend must respect.

A snapshot of the backend's OpenAPI schema is checked in as `openapi.json` at the repo root. **The frontend never invents endpoints, fields, or shapes** — every request and response goes through the generated client.

When the spec and this document disagree, this document wins (and the disagreement is a bug — report it, do not silently choose).

---

## 1. Project shape

- One repository: `s_agent_admin`. **No monorepo, no workspaces.**
- One Vite project, **two entry points**: `/admin` and `/testchat`. Both share an API client, design tokens, auth, layout primitives, and i18n.
- Both UIs are protected by the same backend Basic Auth (`ADMIN_LOGIN` / `ADMIN_PASSWORD`). One login screen serves both.
- Not bundled with the backend. Deployed independently. In dev the Vite dev server proxies API calls to the backend; in prod a reverse proxy serves the static build on the same origin as the backend.
- Locale: **`ru` only on MVP**; architecture supports more (see §10).

## 2. Stack — fixed versions and choices

| Concern | Choice |
|---|---|
| Build tool | **Vite 5** |
| Language | **TypeScript, `strict: true`** |
| Framework | **React 18** |
| Package manager | **pnpm 9+** (`packageManager` field pinned in `package.json`) |
| Node | **20 LTS** (`.nvmrc` and `engines` in `package.json`) |
| Router | **TanStack Router v1** (file-based routes, code-splitting per route) |
| Server state | **TanStack Query v5** |
| Forms | **React Hook Form** + **zod** (resolver: `@hookform/resolvers/zod`) |
| UI primitives | **shadcn/ui** (Radix-based, code generated into the repo, not a node_module dep) + **Tailwind CSS v3** |
| Icons | **lucide-react** |
| Charts | **Recharts** (Dashboard only) |
| API client | **`openapi-typescript`** to generate types from `openapi.json`, **`openapi-fetch`** as the runtime client |
| SSE | **native `fetch` + ReadableStream** (no `EventSource` — it does not support headers, and we need Basic Auth) |
| Date/time | **date-fns** + **date-fns-tz** for user-locale rendering |
| Lint | **ESLint 9** flat config + `@typescript-eslint` + `eslint-plugin-react-hooks` + `eslint-plugin-react-refresh` |
| Format | **Prettier** |
| Tests | **Vitest** (unit + component), **@testing-library/react**, **MSW** (mock backend) for integration tests |
| E2E (optional, not MVP) | Playwright |
| Hooks runner | **lefthook** (faster than husky on Windows; both work; pin lefthook) |

**No alternatives.** No CRA, no Next.js, no Mantine/MUI, no Redux/Zustand for server state (TanStack Query owns it), no Axios (openapi-fetch wraps native fetch), no Moment, no Yup, no Jest. If you find yourself reaching for one, stop and ask.

A piece of client-only state that crosses route boundaries (rare — auth header, theme, current testchat user pick) lives in **React Context + `useState`**, not in a global store. Don't add Zustand on MVP.

**Layer boundaries — strict.** Violating them is a bug.
- Routes never call `fetch` directly. They call feature hooks (`useSessions`, `useConfigPresets`, ...).
- Feature hooks call the typed API client from `src/api/client.ts`. They never assemble URLs by hand.
- `src/components/ui/` (shadcn primitives) never imports from `src/features/*`.
- `src/lib/` is pure: no React, no fetch.
- Generated files (`schema.gen.ts`, `routeTree.gen.ts`) are never edited by hand and are gitignored — they're built by `pnpm gen:api` and `pnpm dev` respectively.

## 4. Contracts that every stage must respect

These mirror the backend contracts. Every stage that touches them uses exactly these shapes.

### 4.1. API client

A single instance lives in `src/api/client.ts`:

```ts
import createClient from "openapi-fetch";
import type { paths } from "./schema.gen";

export const api = createClient<paths>({
  baseUrl: import.meta.env.VITE_API_BASE_URL ?? "",
  // BasicAuth header is injected by a middleware that reads from auth context.
});
```

- The dev server proxies `/admin/api`, `/testchat/api`, `/api/chat`, `/health`, `/api/openapi.json` to the backend (see §6). In prod, same origin.
- `VITE_API_BASE_URL` is **empty by default** — same-origin assumed. It exists only as an escape hatch.
- Auth middleware reads the session-stored Basic credentials and adds `Authorization: Basic <base64>`. On 401 it redirects to `/login` and clears storage.

### 4.2. Error envelope

The backend always returns this shape on errors (locked, see backend `CLAUDE.md` §4.5):

```ts
type ErrorEnvelope = {
  error: {
    code: string;        // e.g. "auth_invalid", "config_validation_error"
    message: string;     // localized
    details?: Record<string, unknown> | null;
  };
};
```

`src/api/errors.ts` exports `parseError(unknown): ErrorEnvelope | null`, `errorMessage(code: string): string` (localized fallback), and `isAuthError(err)` so the auth context can react.

### 4.3. Pagination

Cursor-keyset, locked across the API:

```ts
type Page<T> = { items: T[]; next_cursor: string | null };
```

Use `useCursorPagination` (in `src/hooks/`) that wraps TanStack Query's `useInfiniteQuery` with `getNextPageParam: (last) => last.next_cursor`.

### 4.4. SSE event shapes

Locked, mirror backend `app/api/chat/events.py`. Discriminated union on `event` type:

```ts
type SseEvent =
  | { event: "stage";     data: { stage: string; status: "start" | "end"; duration_ms?: number; meta?: Record<string, unknown> } }
  | { event: "tool";      data: { tool: string; status: "start" | "end"; args?: Record<string, unknown>; result_summary?: string; duration_ms?: number; display_name?: string } }
  | { event: "token";     data: { text: string } }
  | { event: "done";      data: { message_id: string } }
  | { event: "error";     data: { code: string; message: string; details?: Record<string, unknown> } }
  | { event: "cancelled"; data: { reason: string } };
```

The reader in `src/api/sse.ts` is the **only** place that parses the `event:`/`data:`/`\n\n` SSE wire format. It returns an `AsyncIterable<SseEvent>` and supports `AbortSignal` for cancellation. **No `EventSource`** — it does not let us add `Authorization`.

For the tool event's user-facing label, **prefer `display_name` when present**, fall back to `tool`. The backend's i18n stage already populates this.

### 4.5. Auth

Basic Auth, both UIs, single login screen.

- **Storage**: `sessionStorage` under key `ha-admin-auth`, value is `{ login: string, basic: string }` where `basic` is `btoa(\`${login}:${password}\`)`. Cleared on logout, on 401, and on browser close.
- **Login validation**: a successful `GET /admin/api/dashboard/health` with the candidate header is the login check. If it returns 200, credentials are valid. Anything else → show error.
- **Routing**: a route guard in `__root.tsx` redirects to `/login` when `sessionStorage` is empty. After login, redirects to the originally requested URL or `/admin`.
- **No "remember me", no JWT, no refresh tokens.** If MVP grows real auth, that's a separate stage.
- **Testchat impersonation**: the testchat UI sends `user_id` in the request body — that is the documented exception (backend `CLAUDE.md` §5). The dropdown is populated from `GET /testchat/api/users` (returns the four seeded personas).

### 4.6. The "requires restart" banner

Many config writes return `{ requires_restart: true }`. When that happens, store a flag in a global context (`RestartContext`) and render a sticky `<RestartBanner>` at the top of the admin shell with copy: "Some changes require an agent restart to take effect." The flag clears on a manual dismiss button. The banner does **not** disappear automatically — the user has to acknowledge it.

We do not call any restart endpoint from the frontend (none exists, by design — see backend §15.1).

### 4.7. Cancellation

Two cases:

1. **Testchat in-flight message.** `POST /testchat/api/cancel` with `{ session_id, message_id }`. The session id and message id come from the `X-Session-Id` and `X-Message-Id` response headers of `POST /testchat/api/send`. The reader's `AbortController` is also fired so the SSE stream stops locally.
2. **Reindex job.** No cancel endpoint on MVP; the UI only polls `GET /admin/api/config/rag/reindex/{job_id}`.

## 5. Cross-cutting decisions (these resolve open questions)

- **Time zones**: every timestamp from the API is ISO 8601 with `Z`. Render with `date-fns-tz` using **the browser's local zone**. Do not infer the user's profile timezone for admin/testchat — those are operator UIs, not end-user UIs.
- **Money / numbers**: `Intl.NumberFormat` with locale `ru-RU`. No raw `.toFixed`.
- **JSON viewing**: structured payloads (LLM calls' raw prompts/responses, tool args/results, RAG results) are big. Use a single `<JsonViewer>` component (collapsible tree, copy button, depth-based collapse, search). Don't dump them as `<pre>`.
- **Streaming UI**: tokens append to a single message bubble. Stage and tool events render in a separate "thinking" panel that auto-collapses on `done`. Always show `display_name` (fallback to `tool`) in the tool chip.
- **Forms**: every form uses RHF + zod. The zod schema is the source of truth for client-side validation; the server is the source of truth for cross-field rules and final validation. On 400 with `error.details.field_errors` (or similar), surface them as field errors.
- **Tables**: one `<DataTable>` primitive in `src/components/`. Cursor pagination, column-definition-driven, loading + empty states. No ad-hoc tables in feature folders.
- **Loading & error states**: every page has explicit loading, empty, and error states. No bare spinners on top of stale data; use TanStack Query's `keepPreviousData` for paginated lists.
- **Accessibility**: shadcn/ui primitives are Radix-based — keep their semantics. No `<div onClick>` for buttons.
- **Theming**: light + dark, toggle in the header, persisted to `localStorage`. Tailwind `dark:` variants. CSS variables in `src/styles/tokens.css`.

## 6. Dev environment & CORS

The backend has **no CORS middleware** (verified against the current backend). Two consequences:

1. **In dev**, Vite's dev server proxies API requests so the browser sees a same-origin app.

   `vite.config.ts`:
   ```ts
   server: {
     proxy: {
       "/admin/api": "http://localhost:8000",
       "/testchat/api": "http://localhost:8000",
       "/api": "http://localhost:8000",
       "/health": "http://localhost:8000",
     },
   },
   ```

   Backend dev URL comes from `.env.development` (`VITE_BACKEND_URL=http://localhost:8000`). The proxy reads it.

2. **In prod**, the frontend is served from the same origin as the backend by a reverse proxy (nginx or traefik in front of the agent container). The frontend repo ships only the static build — the proxy config lives wherever ops keeps it. We do **not** add CORS to the backend just to enable a different origin in prod.

If at any point a separate origin in prod becomes a real requirement, the right move is to add `CORSMiddleware` on the backend with an allowlist, not to ship credentials cross-origin from the SPA.

## 7. Coding style

Mirror the backend's discipline. The backend's `CLAUDE.md` §7 and §7.1 apply here unchanged. Highlights, in our words:

- **Comments**: only when the code does not say it. No restating signatures, no `// loop through items`, no `// added for the dashboard`. Only the **why** when it's non-obvious. Hygiene rules from backend §7.1 apply unchanged — including the rule against floating string literals as fake section headers.
- **Docstrings (JSDoc on exported functions)**: one short line. Multi-paragraph blocks only when the contract is genuinely non-trivial.
- **Names**: descriptive but short. `useSessions` not `useGetAllSessionsForCurrentUserPaginated`.
- **No emojis** in code, comments, logs, commit messages, or UI strings (unless a designer explicitly designs them in).
- **No `any`**. Use `unknown` and narrow. The generated `paths` type from `openapi-typescript` covers 99% of API shapes.
- **No `console.log`** outside of dev-only debugging. Use `src/lib/log.ts` (a thin wrapper that no-ops in prod).
- **No hardcoded user-facing strings in components**. They live in `src/i18n/ru.ts`. The exception is debug-only labels (e.g. JSON viewer "expand") — those can be English and don't need translation, but document why with a one-line comment.
- **Imports**: absolute imports rooted at `@/...` (Vite + `tsconfig.app.json` `paths`). No `../../../`.
- **Component file naming**: `PascalCase.tsx` for components, `camelCase.ts` for hooks/utils. One component per file as the default; multiple is allowed only when they are truly co-dependent.
- **Props shape**: explicit `type Props = {...}` next to the component, not `React.FC` (which leaks `children`).

## 8. Error handling discipline

- Never catch errors blindly. Catch what you can recover from, let the rest bubble to a route-level `<ErrorBoundary>`.
- A caught error is either: (a) handled meaningfully (turned into a user-visible state with a recovery action), or (b) reported and re-thrown. Never silently swallowed.
- Network errors are **not** auth errors. A 401 from the API → auth context clears + redirect to login. A 5xx → stay, show a retry. A network failure (TypeError from fetch) → "no connection" state.
- TanStack Query handles retries for queries (default `retry: 1`, no retry on 4xx). Mutations: **no retry** by default; the user re-submits.

## 9. Testing rules

- **Unit tests**: every non-trivial pure helper in `src/lib/` and `src/api/`. Run with Vitest.
- **Component tests**: feature components with branchy logic (the SSE-rendering chat panel, the JSON viewer, the cursor table). RTL + Vitest.
- **Integration tests**: feature flows mocked with **MSW** against the real `openapi.json`. Setup in `tests/setup.ts`.
- **No real network**. No real backend. No browser-driven E2E on MVP.
- Every PR/stage: `pnpm test` green, `pnpm typecheck` green, `pnpm lint` green, `pnpm build` green.

- `typecheck` — `tsc --noEmit`
- `test` — `vitest run`
- `test:watch` — `vitest`
- `gen:api` — `openapi-typescript ./openapi.json -o src/api/schema.gen.ts`

## 11. The `openapi.json` snapshot

A copy of the backend's OpenAPI schema is checked in at the repo root as `openapi.json`. It is the **input** to type generation, not the output of it.

Update flow:
1. Backend developer (or you) regenerates the file: `pnpm gen:api:remote` (with backend running) or copies the file from the backend repo.
2. `pnpm gen:api` regenerates `src/api/schema.gen.ts`.
3. TypeScript fails immediately wherever the API surface changed. Fix the call sites — not the types.

Do **not** edit `openapi.json` by hand. Do **not** edit `schema.gen.ts` ever.

## 12. Definition of done — applies to every stage

A stage is done when **all** of the following are true:

1. `pnpm accept-stage` exits zero (typecheck + lint + tests + build).
2. New code has unit / component tests where it has branchy logic.
3. If the stage adds new API consumers, the call sites use the generated types — no `any`, no hand-rolled URLs.
4. If the stage adds new user-facing strings, they are in `src/i18n/ru.ts`.
5. If the stage touches dev-only infrastructure (proxy, env vars, scripts), those changes are documented in `README.md`.
6. The frontend can be built and served, and the relevant feature works end-to-end against a running backend in dev. Verify in a browser. Type checking and tests verify code correctness, not feature correctness — if you can't open a browser to test, say so explicitly.
7. `CHANGELOG.md` has a new entry summarising the stage.
8. If you discovered something during the stage that contradicts or extends `FRONTEND_CLAUDE.md`, propose an update in the same change set rather than silently diverging.
9. **One commit on the `develop` branch** at the end of the stage, following the format in §13.

## 13. Git workflow

Mirrors the backend repo, intentionally. Same single-branch flow, same commit style.

- All work happens on **`develop`**. No feature branches, no GitFlow.
- **One commit per stage**, made at the very end after all checks in §12 pass.
- Commit message format: conventional commits with stage in scope, no emojis, no marketing copy, no co-author lines.

  ```
  <type>(stage-FNN): <short summary in lowercase>

  - <bullet>
  - <bullet>

  Closes stage FNN.
  ```

  Example for stage F1:
  ```
  chore(stage-F01): project skeleton

  - Vite + React + TS strict, pnpm, Node 20
  - TanStack Router file-based routes; admin and testchat shells stubbed
  - openapi-fetch client wired to schema.gen.ts; openapi.json snapshot checked in
  - Basic Auth login screen with sessionStorage; route guard
  - shadcn/ui initialised, Tailwind tokens, light/dark toggle
  - Vitest + MSW set up; one smoke test passing
  - lefthook pre-commit; ESLint flat config; Prettier
  - Makefile-equivalent scripts in package.json (accept-stage)

  Closes stage F1.
  ```

- **Never `git push`** without explicit approval. Never force, never rebase, never reset hard. Backend repo's §14.4 rules apply unchanged.
- After the stage commit, `git status` must be clean.

## 14. What you must not do

- Do not invent endpoints, request/response fields, or error codes that are not in `openapi.json`. If something is missing on the backend, **ask** — do not work around it on the client.
- Do not call `fetch` directly from a component. Always go through `src/api/client.ts` and a feature hook.
- Do not add a dependency that is not in §2 without explicit approval.
- Do not edit generated files.
- Do not bypass the layer boundaries in §3 even "just for one call".
- Do not add `any` to make types pass. `unknown` + narrowing, or fix the upstream.
- Do not change `FRONTEND_CLAUDE.md` without flagging it.

## 15. Locked decisions from completed stages

The archive of locked decisions from completed frontend stages lives in `docs/locked_decisions.md` (in this repo, mirroring the backend's convention). Every stage appends a section there with the form `### Stage F<N>`. Skipped numbers stay skipped. Do not renumber.
